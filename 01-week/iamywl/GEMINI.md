# Tart 인스턴스 실행 스크립트 분석 및 수정 보고서

## 1. 원인 분석 (Root Cause Analysis)

기존 `instance.sh` 스크립트에서 Tart 인스턴스가 제대로 실행되지 않거나 동작이 불안정했던 주요 원인은 다음과 같습니다.

### 1.1. 잘못된 Tart 명령어 사용
- **문제**: 스크립트에서 `tart resize` 명령어를 사용하고 있으나, Tart 2.x 버전에서는 해당 서브커맨드가 존재하지 않습니다.
- **영향**: 디스크 크기 조정 단계에서 오류가 발생하며, 스크립트의 의도대로 리소스가 설정되지 않습니다.
- **해결**: `tart set <VM_NAME> --disk-size <SIZE>` 명령어를 사용해야 합니다.

### 1.2. 불안정한 배경 실행 (Background Execution)
- **문제**: `tart run`을 배경(`&`)으로 실행한 후, VM이 정상적으로 시작되었는지 확인하는 로직이 부족합니다.
- **영향**: 만약 `tart run`이 리소스 부족이나 설정 오류로 즉시 종료될 경우, 이후의 `tart exec` 루프가 무한 대기에 빠지거나 실패하게 됩니다.
- **해결**: VM 프로세스의 생존 여부를 확인하고, 일정 시간 내에 응답이 없으면 타임아웃 처리를 하도록 개선해야 합니다.

### 1.3. 매번 인스턴스 삭제 및 재생성
- **문제**: 실행할 때마다 `tart delete`와 `tart clone`을 수행합니다.
- **영향**: 매번 20GB 이상의 이미지를 복사하고 `apt-get update` 및 패키지 설치를 수행하므로 실행 시간이 매우 오래 걸리고 비효율적입니다.
- **해결**: 이미 VM이 존재한다면 삭제하지 않고 `tart start`만 수행하도록 로직을 개선할 수 있으나, 이번 수정에서는 안정성을 위해 기존 흐름을 유지하되 속도를 개선하는 방향으로 검토합니다. (사용자 요청에 따라 스크립트 구조를 유지하며 버그 수정에 집중)

### 1.4. APT 락(Lock) 이슈
- **문제**: Ubuntu 부팅 직후 `apt-get update`를 수행하면, 시스템의 자동 업데이트 프로세스가 `dpkg` 락을 점유하고 있어 실패하는 경우가 잦습니다.
- **해결**: APT 락이 해제될 때까지 대기하거나, 실패 시 재시도하는 로직이 필요합니다.

### 1.5. SSH 키 주입 방식의 취약성
- **문제**: `echo '$(cat ...)'` 방식은 SSH 키가 여러 줄이거나 특수 문자가 포함된 경우 쉘 해석 과정에서 깨질 위험이 있습니다.
- **해결**: `tart exec -i`를 사용하여 표준 입력을 통해 직접 전달하는 방식이 더 안전합니다.

## 2. 수정 사항 (Changes)

### 2.1. 명령어 수정
- `tart resize $VM_NAME --disk 50` -> `tart set $VM_NAME --disk-size 50`

### 2.2. 안정성 강화
- `tart run` 실행 후 로그 파일(`/tmp/ossca_vm.log`)을 실시간으로 확인하거나, VM 상태를 체크하는 로직을 보강했습니다.
- Guest Agent 응답 대기 루프에 최대 시도 횟수(Timeout)를 추가하여 무한 루프를 방지했습니다.

### 2.3. 환경 설정 최적화
- `virtiofs` 마운트 시 이미 마운트되어 있는 경우를 대비해 처리 로직을 개선했습니다.
- `apt-get` 설치 시 `-y` 옵션과 함께 `DEBIAN_FRONTEND=noninteractive`를 설정하여 인터랙티브 팝업으로 인한 중단을 방지했습니다.

### 2.4. 스크립트 가독성 및 출력 개선
- 각 단계의 성공/실패 여부를 명확히 출력하도록 변경했습니다.
